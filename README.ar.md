# hunt

تابِع بحثك عن عمل لوحةً من عمليات التوظيف.

hunt برمجيات حرة، بموجب رخصة [GNU AGPL v3](LICENSE): شغّله بنفسك، لنفسك أو لغيرك. وهو من
منتجات [معامل آرابيسك](https://arabesquelabs.com/ar/)، التي تشغّله أيضًا لمن يفضّلون ألا
يستضيفوه بأنفسهم.

لتجرّبه على جهازك، بـDocker أو بـRust، ثم افتح http://localhost:4848:

```sh
docker run -p 4848:4848 -v hunt-data:/data ghcr.io/arabesquelabs/hunt
cargo install --git https://github.com/ArabesqueLabs/hunt && hunt serve
```

ليس لـhunt الخاص بشخص واحد تسجيل دخول خاص به: أبقِه على جهازك، أو ضعه خلف شيء له تسجيل دخول.
وللعمل على hunt نفسه:

يشغّل `hunt serve` خدمة واحدة. تملك قاعدة البيانات (SQLite أو PostgreSQL أو MySQL)
وتقدّم واجهة برمجة JSON، وواجهة ويب تستخدم تلك الواجهة. وبقية أوامر `hunt` تستخدم الواجهة
نفسها، فيتّفق سطر الأوامر والمتصفح دائمًا.

```sh
make serve                      # http://127.0.0.1:4848, database ~/.hunt/hunt.db, for several people (as dev-tenants)
make dev                        # the same, with a throwaway database in target/
make demo                       # fill that throwaway database with demo data (replacing it)
make watch                      # serve it for several people, rebuilding and restarting on every change
make                            # every target: build, release, test, lint, fmt, ci, install…
```

## قاعدة البيانات

يحدّدها `--db` (أو `HUNT_DB`، أو `make serve DB=…`):

```sh
hunt serve --db ~/.hunt/hunt.db                              # SQLite, a file (the default)
hunt serve --db postgres://hunt:secret@localhost/hunt        # PostgreSQL (12 or later)
hunt serve --db mysql://hunt:secret@localhost:3306/hunt      # MySQL (8.0.16 or later)
```

- **يجب أن تكون قاعدة البيانات فارغة، أو قاعدة hunt.** الفارغة تحصل على جداول hunt عند أول
  تشغيل؛ ولـPostgreSQL وMySQL، أنشئ قاعدة البيانات أولًا (`CREATE DATABASE hunt`).
- **الترقيات:** تُرقّى قواعد بيانات SQLite في مكانها حين يفتحها hunt أحدث. أما قواعد
  PostgreSQL وMySQL فتبدأ بالمخطط الحالي؛ ولنقل إحداها عبر تغيير في المخطط، خذ نسخة احتياطية
  منها بـhunt الذي أنشأها واستوردها في قاعدة بيانات جديدة.
- **الاتصالات:** يُتّصل بـPostgreSQL وMySQL دون TLS، فاستخدمهما على الجهاز نفسه أو على شبكة
  خاصة.
- **الاختبارات:** يشغّل `make db-up` الخادمين كليهما في Docker؛ ويشغّل `make test-all`
  اختبارات الواجهة على SQLite وPostgreSQL وMySQL.

## في حاوية، أو على Kubernetes

يبني `Dockerfile` صورة صغيرة (بلا صدفة، وتعمل بمستخدم غير الجذر). تستمع على :4848، وتحفظ
SQLite في `/data` (اربط وحدة تخزين هناك)، وتجيب على `/healthz` حين تجيب قاعدة بياناتها. ويمكن
أن يشير `HUNT_DB` إلى PostgreSQL أو MySQL بدلًا منها.

```sh
docker build --platform linux/amd64 -t hunt .
docker run -p 4848:4848 -v hunt-data:/data hunt
```

يشغّل سير العمل `image` (`.github/workflows/image.yml`) الأمر `make ci`، ثم ينشر
`ghcr.io/arabesquelabs/hunt` (`latest` من main، و`v<version>`، والبصمة sha لكل إيداع)، فلا
تحتاج إلى بنائها بنفسك. وبـDocker Compose:

```yaml
services:
  hunt:
    image: ghcr.io/arabesquelabs/hunt:latest
    ports: ["4848:4848"]
    volumes: ["hunt-data:/data"]
    restart: unless-stopped
volumes:
  hunt-data:
```

تعيد عمليات البناء استخدام ما تستطيع. يبني الـDockerfile اعتماديات hunt في طبقة خاصة بها، من
وصفة [cargo-chef](https://github.com/LukeMathWalker/cargo-chef) (ما يعتمد عليه hunt، دون إصداره
هو)، ويحفظ سير العمل الطبقات في ذاكرة GitHub Actions المؤقتة. تغيير في الشيفرة أو إصدار جديد لا
يترجم إلا hunt نفسه؛ وتغيير الاعتماديات يترجمها من جديد. وتتسع الذاكرة المؤقتة لـ10 غيغابايت لكل
مستودع، فبناء كامل بين حين وآخر، بعد حذف المدخلات القديمة، أمر متوقع.

على Kubernetes، hunt حاوية (pod) واحدة بوحدة تخزين واحدة. ولا يمكن تشغيل إلا نسخة واحدة في كل
مرة، لأن SQLite ملف على تلك الوحدة، فالتحديثات تستبدل الحاوية بدل أن تتدرّج. شغّل سطر الأوامر
عليها عبر تحويل منفذ (`kubectl -n hunt port-forward svc/hunt 4848`، ثم
`HUNT_URL=http://127.0.0.1:4848`).

### ما هو عام، وما يحتاج إلى تسجيل الدخول

لوحة التحكم تحت **`/app`**، وبياناتها تحت **`/api`**: وهما الجزآن الوحيدان اللذان يحتاجان إلى
تسجيل الدخول. وكل ما عداهما عام: الصفحة الرئيسية (`/`)، وهذا التوثيق (`/docs`)، وإشعار الخصوصية
وشروط الاستخدام وصفحة حذف البيانات، والخطوط والنصوص البرمجية والشعار، ونسخها العربية تحت `/ar/`.
والعناوين القديمة (`/board`، `/companies/3`) تقود إلى الصفحة نفسها تحت `/app`.

لذا، خلف Cloudflare Access، احمِ هذين فقط: أعطِ تطبيق Access وجهتين، `hunt.example.com/app`
و`hunt.example.com/api`، بدل اسم المضيف كله. وفي hunt مشترك، يتحقق hunt أيضًا من الرمز الموقّع من
Access في كل طلب للبيانات، فلا يكشف خطأٌ في إعداد Access بيانات أحد.

ليس لـhunt تسجيل دخول خاص به؛ ضع واحدًا أمامه. خلف Cloudflare Access، في الشريط الجانبي
**تسجيل الخروج** (ينهي جلسة Access)، وفي «معلومات التصحيح» في مركز الإدارة الهوية التي يحملها
Access لك ولوحة تحكم Zero Trust، مع فحص سلامة hunt ورابط اشتراك التقويم والنسخة الاحتياطية والشيفرة المصدرية
وعمليات بناء الصورة. وخلف Cloudflare Access، يستخدم سطر الأوامر رمز خدمة: اضبط
`HUNT_ACCESS_CLIENT_ID` و`HUNT_ACCESS_CLIENT_SECRET` على معرّفه وسرّه، و`HUNT_URL` على العنوان
العام. وإشارة «أرسل إلى hunt» المرجعية تفتح hunt في تبويب، فتسجّل الدخول كأي زيارة أخرى.

## النسخ الاحتياطي

الإعدادات ← **النسخ الاحتياطي والاستيراد**، أو `hunt backup` و`hunt restore`.

- **ما في النسخة:** ملف JSON واحد فيه كل شيء (العمليات، والطلبات، والشركات، والأشخاص، والملفات،
  والوسوم، والإعدادات، وسجل التغييرات). ويُستبعد اتصال Gmail، فلا تكون في نسخة احتياطية أبدًا
  كلمة مرور أو بيانات تسجيل دخول.
- **النقل بين قواعد البيانات:** النسخة الاحتياطية تعمل مع أيٍّ منها، فهي تنقل البيانات أيضًا من
  واحدة إلى أخرى، كمن SQLite إلى PostgreSQL.
- **الاستيراد:**
  - يستبدل كل شيء، كله أو لا شيء: نسخة لا تناسب تترك الأمور كما كانت؛
  - يقول ما يحويه الملف ويسأل أولًا؛
  - لا يقبل إلا النسخ الاحتياطية بإصدار المخطط الحالي.

## واجهة الويب

- **لوحة المتابعة**، بعرضين (المبدّل في الأعلى؛ تُفتح كما تركتها):
  - **لوحة** (`/app`): انظر أدناه.
  - **جدول** (`/app/applications`): كل طلب، بمرحلته وما إذا كان نشطًا أو مؤرشفًا أو ليس على
    اللوحة؛ والأجر بالجنيه الإسترليني، والموقع، ونمط العمل، والمصدر، ومتى قُدّم ومتى تغيّر آخر
    مرة، والوسوم. رتّب بأي عمود؛ وافتح الطلب من صفّه.

  **عوامل التصفية**، المشتركة بين العرضين: كلمات (الشركة، المسمّى، الموقع، المصدر، الوسوم،
  الأشخاص)، وما يحتاج إلى انتباه (مقابلة خلال 7 أيام، أو لم يتغيّر منذ 14 يومًا فأكثر)، ونمط
  العمل، والأجر (حدّ أدنى سنوي بالجنيه، تُحوَّل إليه العملات الأخرى وتُحسب الفترات الأخرى سنويًا؛
  و«الراتب المعروف فقط» يستبعد ما لا أجر له)، والمصدر؛ وتحت «مزيد من عوامل التصفية»: الشركة،
  والشخص، وما أُضيف أو قُدّم إليه في آخر 7/30/90 يومًا، وما يُغلق قريبًا، والموقع، ونوع التوظيف،
  وسبب الأرشفة، وما له رسائل/ملفات/أشخاص (أو لا شيء)، والحالة والوسم. وهي في العنوان
  (`/app?mode=remote&pay=120000`)، فيمكن حفظ عرض مصفّى في المفضلة، ويتراجع زر الرجوع عن التغيير؛
  وتنتقل بين العرضين وتُتذكَّر. ويظهر «مسح عوامل التصفية» وعدد ما يُعرض متى كان أيٌّ منها مفعّلًا.
- **اللوحة.** عمود لكل مرحلة؛ والأعمدة تطول ببطاقاتها. البطاقات مختصرة (المسمّى والشركة) أو
  مفصّلة، بمفتاح «مفصّل» في آخر صف عوامل التصفية. اسحب البطاقات بين الأعمدة أو داخل العمود.
  و«+ إضافة عملية» أسفل العمود تضيف عملية فيه مباشرة:
  - الصق رابط إعلان الوظيفة، فيملأ ما فيه المسمّى والشركة والموقع ونمط العمل والأجر والتواريخ
    ونص الإعلان؛
  - أو اكتفِ بالشركة (تُكمَل تلقائيًا، ويُعرض إنشاء شركة لا يعرفها)، والمسمّى والمصدر.
- **إعلان متابَع من قبل** يُنبَّه إليه حين تلصق رابطه، أو تضعه على طلب: يسمّي التحذير الطلب وأين
  عملياته. وتتطابق الروابط مهما نُسخت (معاملات التتبع، و`www.`، و`?currentJobId=` في LinkedIn).
  وهو تحذير فقط؛ يمكنك إضافته مع ذلك، كما حين تتقدّم مرة أخرى.
- **إعلانات الوظائف** تُقرأ من Ashby وGreenhouse وLever وWorkable وLinkedIn وApple Careers
  وlevels.fyi (`levels.fyi/jobs?jobId=…`؛ وصفحاتها `/jobs/view/…` هي وظائف LinkedIn، تُقرأ من
  LinkedIn)، ومن أي صفحة وظائف تصف وظائفها ببيانات `JobPosting` من schema.org، كما تفعل معظم
  مواقع الوظائف. ويُحتسب نطاق الأجر المكتوب في النص («$180,000 – $220,000») حين لا يعطي الإعلان
  أجرًا بيانات. ويمكن لطلب موجود أن يستورد إعلانه أيضًا («الاستيراد من رابط…»)، فيختار ما يأخذ.
- **أكثر من إعلان**: كثيرًا ما تُنشر الوظيفة نفسها في أكثر من مكان (صفحة الوظائف، وLinkedIn،
  ووكالة). رابط الطلب نفسه هو إعلانه الرئيسي؛ و«+ إضافة رابط إعلان» يضيف غيره، كلٌّ محفوظ بنصه
  ومتى قُرئ آخر مرة (`hunt list postings`). ويُقرأ الرابط حالما يُضاف، وكذلك رابط إعلان غُيّر في
  التعديل. و«الاستيراد من رابط…» (أو «تحديث الكل») يقرأ كل الروابط دفعة واحدة، و«تحديث» كلٍّ منها
  يقرؤه وحده. وما تقوله يُعرض جنبًا إلى جنب، باختيار واحد لكل حقل: ما هو موجود الآن، أو ما يقوله
  رابط ما، مع ≠ حيث تختلف الروابط. ويُبقى ما هو موجود ما لم يكن فارغًا، حتى تختار غير ذلك؛ ويُحفظ
  نص كل رابط لذلك الرابط. والرابط الموجود لدى طلب آخر، بأي من النوعين، يُحذَّر منه.
- **كثير دفعة واحدة.** حدّد عمليات في الجدول (مربع اختيار لكل صف، وواحد في الترويسة لكل الصفوف
  المعروضة، وshift مع النقر لمجموعة متتالية)، أو على اللوحة (Ctrl/⌘ مع النقر على بطاقة، أو اضغط x
  عليها؛ وEscape يُلغي التحديد). فيعرض شريط: نقل إلى (مرحلة، أو مسار فيها)، وأرشفة… (سبب
  وملاحظة واحدة للجميع)، واستئناف، وإضافة وسم…، وإزالة وسم…، والإجراء التالي…، وحذف…. وسحب
  بطاقة محدّدة على اللوحة يجلب الأخرى معها (إلى عمود، أو مسار، أو الأرشيف). وكل تغيير كله أو لا
  شيء، ويُسجَّل على كل عملية، وتعرض رسالة منبثقة التراجع. والشركات والأشخاص والملفات لها مربعات
  الاختيار نفسها، لوسمها أو إزالة وسمها أو حذفها معًا. ويفعل `POST /api/processes/bulk` ذلك
  لواجهة البرمجة، ويقبل سطر الأوامر عدة عمليات معًا: `hunt move globex,initech screening`،
  `hunt archive tag:agency role-filled`، `hunt move stage:Applied interviewing`.
- **قبول عرض**: على طلب وصل إلى عرضه (مرحلة العرض، أو الأخيرة)، ينقله «🎉 قبول العرض…» إلى مسار
  «مقبول» في المرحلة، مع ملاحظة (تاريخ البدء مثلًا). والقبول ليس نهاية: قد تكون المراجع والتحقّقات
  والبدء ما تزال أمامك، فيبقى على اللوحة حتى يُغلق بـ«بدأت العمل» (والمرحلة التي لا مسار «مقبول»
  فيها تُغلقه هكذا مباشرة). ثم تُختم العمليات المفتوحة الأخرى، كلٌّ كما يُختار: تُغلق (انسحابًا، مع
  ذكر العرض)، أو تبقى مفتوحة مع تذكير للغد بإبلاغ مسؤول التوظيف (الافتراضي من مرحلة الفرز
  فصاعدًا)، أو تُترك كما هي؛ أو كلها دفعة واحدة. ومن حينها تحتفل الصفحة الرئيسية بالعرض: المسمّى
  والأجر والملاحظة، وتحتها كيف سار البحث (الأيام من أول طلب إلى الموافقة، والطلبات، والشركات،
  والمقابلات، والأشخاص، والعروض)، والأشخاص في العملية، لتشكرهم. و«العودة إلى اللوحة» تُرجع
  اللوحة إلى الصفحة الرئيسية (في هذا المتصفح)؛ و«عرضك» في الشريط الجانبي يعرض الاحتفال مرة أخرى.
- **إخفاء مرحلة**: العين في ترويسة العمود تُخفي تلك المرحلة من اللوحة؛ وتُسرد المراحل المخفية فوق
  الأعمدة، بأعدادها، لإظهارها مجددًا (واحدة واحدة، أو كلها). يُتذكَّر ذلك في هذا المتصفح؛ وبطاقاتها
  ما تزال تُحتسب، وتظهر في الجدول.
- **المسارات**: صفوف اللوحة، من الأعلى إلى الأسفل، في كلٍّ منها مراحل (أعمدته). في hunt الجديد
  مساران: العمليات الجارية والعمليات المنتهية. أضفها أو أعد تسميتها أو ترتيبها أو أزلها في
  الإعدادات ← اللوحة، واختر هناك مسار كل مرحلة (والمرحلة التي ليست في أي مسار تكون في الأول).
  وكل مسار يُطوى إلى ترويسته وعدده؛ ومفتاحه «مطوية» يحدد كيف يبدأ (مفتوحًا، ما لم يُفعَّل)، وفتحه أو
  طيّه على اللوحة يُتذكَّر في هذا المتصفح.
- **المراحل الفرعية**: يمكن تقسيم عمود المرحلة، من الأعلى إلى الأسفل. في hunt الجديد ثلاث، كلٌّ
  منها انتظار يستحق التمييز دون عمود خاص به: قيد التحضير (تحت قيد الدراسة)، وبانتظار القرار
  (المقابلات) ومقبول (العرض). أضفها أو أعد تسميتها أو أزلها في الإعدادات ← اللوحة، حيث تُسرد
  المراحل الفرعية لكل مرحلة مزاحةً تحتها. أسقط بطاقة في إحداها، أو اخترها في صفحة البطاقة؛ والبطاقات
  التي ليست في أيٍّ منها تبقى أعلى العمود، والبطاقة المنقولة إلى مرحلة أخرى تغادر مرحلتها الفرعية.
  ويعرض الجدول «العرض · في القائمة المختصرة»؛ و`hunt move acme offer --lane shortlisted` من سطر
  الأوامر (واجهة البرمجة وسطر الأوامر يسمّيانها lanes). ويمكن أن تكون المرحلة الفرعية الافتراضية
  لمرحلتها (مفتاح «الافتراضية»): البطاقة الداخلة إلى المرحلة دون تحديد (نقل إلى، أو طلب جديد، أو
  سطر الأوامر، أو إعادة الفتح) تذهب إليها؛ والبطاقة المُسقطة أعلى العمود تبقى في الأعلى.
- **الإغلاق مرحلة.** يمكن أن تكون المرحلة مرحلة نهائية (الإعدادات ← اللوحة). والعملية في مرحلة
  نهائية مغلقة، والمرحلة الفرعية التي هي فيها تقول السبب: في hunt الجديد ثلاث مراحل نهائية، في
  العمليات المنتهية، مراحلها الفرعية هي الأسباب: قراري (انسحبت، رفضت العرض … بدأت العمل)، وقرارهم
  (رفضوني، شُغل المنصب …) ومعلّقة / متوقفة (معلّق، انقطعوا عن التواصل …). أضف سببًا مرحلةً فرعية،
  أو مرحلة نهائية أخرى؛ اجعل أي مرحلة نهائية فيُغلق ما فيها، وأعدها غير نهائية فيُفتح. والعملية
  المغلقة تحتفظ بآخر مرحلة بلغتها قبل ذلك («وصل إلى المقابلات»)، وبها تحتسبها الإحصاءات والدورات.
  أسقط بطاقة على سبب لتُغلقها به؛ واسحبها إلى عمود آخر لتعيد فتحها، أو أعد فتحها من صفحتها: إلى
  المرحلة التي بلغتها.
- **الطيّ**: تُطوى بطاقات العمود، أو المرحلة الفرعية، في كومة بالسهم في ترويسته: بطاقات فارغة تقول
  كم هي («3 بطاقات»)، أو «فارغة» بإطار متقطّع. والعمود المطوي كله كومة واحدة، مراحله الفرعية فيها؛
  والنقر على كومة يفتحها. ومفتاح «مطوية» للمرحلة (الإعدادات ← اللوحة) يحدد كيف تبدأ بطاقاتها:
  مفتوحة، لكن مطوية للمراحل النهائية التي يبدأ بها hunt. وتبدأ المرحلة الفرعية كمرحلتها، حتى يُضبط
  مفتاح «مطوية» الخاص بها.
- **الطلب** له صفحة خاصة (`/app/applications/ID`): تفتحها بطاقة على اللوحة وصفٌّ في الطلبات
  كلاهما. تُقرأ أولًا، من الأعلى إلى الأسفل:
  - مرحلته (شريط خطوات)، وما إذا كان مؤرشفًا؛
  - الوظيفة: الموقع ونمط العمل ونوع التوظيف أولًا، ثم الأجر (بالجنيه أولًا، وتحته العملة الأصلية
    والسعر؛ والمكافأة والأسهم)، ثم رابط الإعلان والمصدر ومتى تقدّمت؛
  - الخط الزمني: خطوات المقابلات (متى، وبأي شكل، ومع من، والملاحظات) وما حدث، بترتيب التاريخ.
    و«مع من» يختار أشخاصًا من الأشخاص، أو يقبل اسمًا جديدًا يصير شخصًا (في شركة الطلب) حين
    تُحفظ الصفحة؛ وعند القراءة، أسماؤهم روابط إليهم؛
  - ملاحظاتك؛
  - عن الوظيفة: إعلاناتها، كلٌّ معروض كرسالة بريد (من أين، ومتى نُشر ومتى يُغلق، أو متى قُرئ آخر
    مرة، ثم العناوين والقوائم والروابط في مربعه الخاص؛ وفتح ↖، وتحديث، وإزالة لكلها عدا الرئيسي)؛
  - الأشخاص، ببريدهم وهاتفهم للنقر (للمراسلة أو الاتصال)؛ والرسائل، محادثاتٍ (بمحادثة Gmail، أو
    بالموضوع)، مطويّة حتى تُفتح، كل رسالة بوقتها؛ والملفات المرسلة؛
  - الشركة، مطويّة حتى تُفتح، وسجل التغييرات؛
  - الوسوم، ثم الاستيراد من رابط… وأرشفة… وحذف في الأسفل.

  كل قسم يُطوى من ترويسته، ويبقى كما تركته. وعند القراءة، لا تعرض الصفحة نماذج: «+ إضافة شخص»
  و«+ إضافة رسالة» و«+ إرسال ملف» تفتح نماذجها، و«+ إضافة خطوة» أو «+ إضافة حدث» أو «+ إضافة
  ملاحظة» تبدأ التعديل هناك. و**تعديل** يحوّل الصفحة إلى نموذج واحد: غيّر أي شيء، وانقل المرحلة،
  وأضف خطوات وعناصر خط زمني أو أزلها، ثم **حفظ التغييرات** (⌘S) أو **تجاهل**. والمغادرة مع
  تغييرات غير محفوظة تسأل أولًا. والأشخاص والرسائل والملفات تُحفظ حالما تُضاف أو تُزال، في
  الوضعين.
- **الطلبات والشركات والأشخاص**: قوائم قابلة للبحث؛ وكل سجل يُفتح للتعديل، بسجل تغييرات خاص به.
- **استيراد شركة أو شخص**: «الاستيراد من رابط…» على شركة أو شخص جديد، أو في صفحتهما، أو في لوحة
  الشركة في العملية.
  - يقرأ موقع الشركة أو صفحتها على LinkedIn لاسمها وموقعها الإلكتروني وصفحتها على LinkedIn
    وقطاعها وحجمها ومقرّها وسنة تأسيسها ووصفها. وصفحة شركة على levels.fyi
    (`levels.fyi/companies/stripe`) تعمل أيضًا.
  - يعرض ما وجده بجانب ما هو موجود. والحقول الفارغة مؤشَّرة؛ والممتلئة تُبقى ما لم تؤشّرها.
  - لا يُحفظ شيء حتى تختار.
  - يرفض LinkedIn أحيانًا الصفحات دون تسجيل دخول. وحين يفعل، يُقال ذلك؛ فاستخدم موقع الشركة
    نفسه بدلًا منه.
- **أشخاص من LinkedIn**: الملفات الشخصية تحتاج إلى تسجيل دخول، فيقرؤها hunt من متصفحك. اسحب
  «أرسل إلى hunt» من الإعدادات ← LinkedIn إلى شريط الإشارات المرجعية؛ وعلى ملف شخص ما، انقرها.
  فيُفتح hunt باسمه ومسمّاه وشركته وموقعه ونبذته وصورته لتختار منها، ويحدّث من لديه ذلك الملف أصلًا
  بدل إضافته مرتين. ومن يحمل الاسم نفسه، المضاف يدويًا أو برابط آخر، يُسأل عنه أو يُدمج فيه أو يُترك،
  كما تقول الإعدادات؛ وتحفظ الإعدادات أيضًا العنوان الذي تفتح الإشارة hunt عليه، لحين لا يكون عنوان
  هذه الصفحة. والإشارة لا تجمع إلا نص الصفحة؛ وhunt هو من يقرؤه، فتغيير في صفحات LinkedIn يحتاج
  إلى تحديث hunt، لا إلى إشارة جديدة.
- **الملفات**: المستندات وإصداراتها. المستند سيرة ذاتية، أو خطاب تقديم، أو ملف أعمال، أو مرجع، أو
  شهادة أو كشف درجات، أو لقطة شاشة، أو وصف وظيفة، أو مهمة منزلية، أو عرض، أو عقد، أو اتفاقية عدم
  إفصاح، أو تحقّق من الخلفية، أو حق العمل أو هوية، أو مورد للمرشح، أو ملاحظات، أو غير ذلك؛ والقائمة
  تُصفّى بالنوع، ويُخمَّن نوع الملف الجديد من اسمه.
  - أسقط الملفات في أي مكان من الصفحة، أو اخترها (منطقة الإسقاط تحت القائمة): الملف المسمّى
    كمستند يصير إصداره التالي، وأي شيء آخر يصير مستندًا جديدًا، يُخمَّن نوعه من الاسم.
  - أسقط على صفّ لتضيف إصدارًا إلى ذلك المستند.
  - يعرض المستند إصداراته بجانب معاينة: ملفات PDF في عارض المتصفح، والصور، والنصوص. والأنواع
    الأخرى تعرض التنزيل.
  - وسم الإصدارات («rust-focused»)، وانظر مع أي العمليات أُرسل كلٌّ منها. والعملية تسجّل أي
    الإصدارات أُرسلت معها، وتعاينها أيضًا.
- **البريد**: كل عملية تحتفظ بالرسائل الخاصة بها. في لوحة «الرسائل» فيها، أسقط ملفات `.eml`
  (في Gmail: ⋮ ← تنزيل الرسالة)، أو اخترها، أو الصق رسالة (في Gmail: ⋮ ← إظهار الأصل ← نسخ إلى
  الحافظة؛ ولصق الصفحة كلها يعمل أيضًا). كلٌّ تعرض من ومتى والموضوع وبدايتها، وتُفتح على النص كله،
  وترتبط بها في Gmail. والبطاقات تعدّها. (تسجيل الدخول إلى Gmail ومزامنته، ومطابقة البريد
  بالعمليات تلقائيًا، مبنية لكنها معطّلة الآن: `GMAIL` في `src/web/app.js`.)
- **الملاحظات**: ملاحظات عامة، عن البحث لا عن طلب واحد (ما تريده تاليًا، والأسئلة التي تطرحها):
  قابلة للبحث والوسم، وتُعدَّل في مكانها.
- **التقويم** (`/app/calendar`): المقابلات والمواعيد النهائية للطلبات في العمليات النشطة، بالشهر أو
  الأسبوع أو اليوم أو جدول أعمال، مع البحث بالشركة أو المسمّى أو العنوان. الأسبوع واليوم من منتصف
  الليل إلى منتصف الليل، كل حدث في وقته؛ والساعات خارج ساعات عملك مظلّلة، ويمكن أن تسير ساعات مناطق
  زمنية أخرى بجانب ساعاتك (كلاهما في الإعدادات ← التقويم، التي تفتحها الأيقونة بجانب البحث).
  والمقابلات التي جرت أهدأ، والملغاة تُستبعد؛ والموعد النهائي يظهر حتى تتقدّم. و«عطلات نهاية
  الأسبوع» يُظهر السبت والأحد أو يخفيهما. ومفتاح تحت التقويم يشرح معاني ألوانه. والعرض وخيار عطلة
  نهاية الأسبوع في العنوان (`/app/calendar?view=week&weekends=hide`)، فيتراجع زر الرجوع عن التغيير،
  ويُتذكَّران.
- **الإحصاءات** (إحصاءات المقابلات): لوحة معلومات للبحث: ما هو قادم أولًا، ثم الطلبات النشطة، وإلى أي
  مدى تقدّمت في المراحل، وما أُضيف وكم مقابلة كل أسبوع، ولماذا انتهت العمليات، وأيّ المصادر تصل
  أبعد، وأنماط العمل، والأجور المعروضة (بالعملة الرئيسية)، وكم يستغرق كل شيء، والنشاط يومًا بيوم،
  وما خفت، والسجلات المحفوظة، جدولًا جدولًا. وأرقام كل رسم بياني جدول أيضًا. وتحت **موارد
  النظام**، ما يستخدمه hunt من جهازه، يُحدَّث كل 5 ثوانٍ ما دامت الصفحة مفتوحة: الذاكرة (مقابل حد
  الحاوية، على Linux)، والمعالج الآن وفي المتوسط، والحمل، وحجم قاعدة البيانات والملفات المخزّنة،
  والمساحة الحرة على قرصها (SQLite) (`GET /api/system`). و«مدة التشغيل» تُحتسب عبر إعادات التشغيل
  والنشر: يحتفظ hunt بنبضة كل دقيقة في قاعدة بياناته، والتشغيل بعد أقل من 15 دقيقة من آخر نبضة
  يُكمل مدة التشغيل.
- **العناوين** مسارات حقيقية (`/app/applications/2`، `/app/stats`): زرّا الرجوع والتقدّم يعملان،
  ويمكن حفظ الصفحات في المفضلة. والروابط القديمة `/#/…` ما تزال تعمل.
- **صفحات لكل شيء**: الشركات (`/app/companies/3`) والأشخاص والمستندات تُفتح في صفحات خاصة بها،
  مصنوعة كصفحة الطلب: تُقرأ أولًا، و«تعديل» يحوّل التفاصيل إلى نموذج يُحفظ بـ«حفظ التغييرات» أو
  يُتجاهَل. والأشياء المرتبطة في أقسام تُطوى (طلبات الشركة وأشخاصها، وإصدارات المستند)، ثم سجل
  التدقيق. والوسوم وإجراءات السجل كله (الاستيراد، والشعار أو الصورة، والحذف) في الأسفل. وللشركات
  والأشخاص والمستندات الجديدة صفحات أيضًا (`/app/companies/new`)؛ ولا يُفتح فوق الصفحة إلا الطلب
  الجديد. ورابط الملف يفتح صفحة مستنده على ذلك الإصدار.
- **الوسوم** توضع على الطلبات والشركات والأشخاص والمستندات: «+ إضافة وسم» أسفل كل صفحة، باختيار
  وسم موجود أو كتابة وسم جديد. والبطاقات تعرض وسوم طلبها حين تكون مفصّلة؛ واللوحة والقوائم تُصفّى
  بالوسم.
- **الإعدادات**، في مجموعات تُطوى (وتُتذكَّر). الأقسام تُقرأ أولًا؛ و«تعديل» القسم، أو تعديل صفّ أو
  إزالته أو «+ إضافة …»، يفتحه للتغيير.
  - المظهر: السمة (محفوظة لكل متصفح)، واللغة والمنطقة: اللغة (الإنجليزية أو العربية؛ انظر اللغات
    أدناه)، والمنطقة التي تُكتب التواريخ والأرقام لها، وأي الأرقام تُستخدم، والوقت بنظام 24 أو 12
    ساعة، والعملة الرئيسية. ويبقى الأجر محوَّلًا إلى الجنيه ومحفوظًا هكذا؛ ويُعرض بالعملة الرئيسية
    بسعر اليوم من الجنيه (يُجلب حين تُختار، وحين يبدأ hunt).
  - اللوحة: المسارات، والمراحل والمراحل الفرعية، كل مرحلة بمراحلها الفرعية مزاحةً تحتها، ومسارها،
    ومفتاحيها «مرحلة نهائية» و«مطوية»: أضف وأعد التسمية والترتيب وأزل. والمراحل الفرعية للمراحل
    النهائية هي أسباب الإغلاق. والمرحلة المستخدمة تسأل إلى أين تذهب عملياتها؛ والمرحلة الفرعية المزالة
    تترك بطاقاتها في المرحلة (مغلقة دون سبب مذكور، في المرحلة النهائية).
  - الوسوم: أضف وأعد التسمية والتلوين وأزل.
  - التقويم: منطقتك الزمنية، واليوم الذي يبدأ به الأسبوع، وساعات العمل (من، وإلى، وأي الأيام)، وحتى
    ثلاث مناطق زمنية أخرى، ومشاركة التقويم (رابط خاص لتطبيقات التقويم).
  - النسخ الاحتياطي والاستيراد.
  - إشارة LinkedIn المرجعية (مطويّة في البداية): الإشارة، والعنوان الذي تفتحه، وما يُفعل باسم
    موجود هنا من قبل.
- **القوائم** (الشركات والأشخاص والملفات وجدول لوحة المتابعة) تنتهي كل صفّ فيها بالتعديل (صفحته،
  مفتوحة في وضع التعديل: `?edit=1`) والإزالة؛ والشركة أو الشخص الذي له رابط على LinkedIn له التحديث
  أيضًا. وكل عمود عدا الأول في ترويسته عين تخفيه؛ وتُسرد المخفية فوق الجدول، لإظهارها مجددًا (واحدًا
  واحدًا، أو كلها)، وكل جدول يتذكّر أعمدته.
- **صفحة الشركة** تسرد طلباتها، كلٌّ بمرحلته (مرحلة أحدث عملية نشطة له، أو أحدث عملية، مؤرشفةً،
  ولماذا) ووسومه؛ ثم الأشخاص فيها.
- **التحديث من LinkedIn**: الشركة أو الشخص الذي له رابط على LinkedIn يجده مكان «الاستيراد…» (وفي
  القوائم كتحديث)، فيقرأ ذلك الرابط مجددًا. ويحجب LinkedIn معظم الملفات عمّن لم يسجّل الدخول؛ فيعرض
  حينها فتح الملف الشخصي، لإشارة «أرسل إلى hunt».
- **النشاط**: كل تغيير، الأحدث أولًا.

يضم الشريط الجانبي الأقسام، مع الإعدادات (وتسجيل الخروج، خلف Cloudflare Access) وإصدار hunt في
أسفله، مربوطًا بإصداره على GitHub (الوسم `v…`).

## عدة أشخاص (تعدد المستخدمين)

يمكن لـhunt واحد أن يخدم عدة أشخاص، كلٌّ يرى ويغيّر طلباته وشركاته وأشخاصه وملفاته وملاحظاته
ووسومه وإعداداته وحده. يتشاركون قاعدة بيانات واحدة: كل صف يحمل مالكه، وكل طلب يعمل باسم الحساب
الذي جاء منه (يقصر `src/scope.rs` كل استعلام على صفوف الحساب، فلا يحتاج شيء إلى أن يتذكّر ذلك).
وتفعيله يحتفظ بما هو موجود: يصير ملكًا لأول مسؤول.

```sh
hunt serve --tenants --admins you@example.com,other-admin@example.com \
  --access-team yourteam --access-aud <the Access application's AUD tag>
# or HUNT_TENANTS=1 HUNT_ADMINS=… HUNT_ACCESS_TEAM=… HUNT_ACCESS_AUD=…
```

- **تسجيل الدخول** مهمة Cloudflare Access: تسجّل دخول الناس بـGitHub وLinkedIn (أو أي طريقة دخول
  مُعدّة هناك) وتسلّم hunt رمزًا موقّعًا، يتحقق منه hunt بمفاتيح الفريق ووسم جمهور التطبيق. والطلب
  الذي لم يأتِ عبر Access لا يمكن أن ينتحل صفة أحد. ولكي يطلب الآخرون حسابًا، يجب أن تسمح لهم سياسة
  تطبيق Access بالدخول: Include ← Login Methods ← GitHub وLinkedIn (أي من سجّل الدخول بأحدهما)،
  بدل بريدك الإلكتروني.
- **قائمة الوصول المبكر**: طلب حساب يُقدَّم انضمامًا إلى قائمة وصول مبكر، بلا مواعيد ولا وعود. والقادم
  الجديد، بعد تسجيل دخوله، لا يرى إلا «انضم إلى قائمة الوصول المبكر»: اسمه، واختياريًا، ما الذي جاء
  به إلى hunt. وإلى أن يُدخله مسؤول، يرى أنه على القائمة؛ وإن رُفض، يمكنه الانضمام مجددًا.
- **مركز الإدارة** (/admin، للمسؤولين): قائمة الوصول المبكر، لإدخال الناس أو رفضهم (مع ملاحظة)، وكل
  حساب: حالته، ودوره (اجعله مسؤولًا آخر)، وطلباته، ومتى شوهد آخر مرة، ورمز سطر الأوامر الخاص به؛
  عطّله أو فعّله أو أزله (مع كل ما يخصه، إن اخترت)؛ ومفتاح لتحديد ما إذا كان يمكن للجدد طلب حساب
  أصلًا (مغلقًا، يُقال لهم إن القائمة مغلقة حاليًا؛ والحسابات الموجودة تستمر). وفي «معلومات التصحيح»
  روابط في المتناول: هوية Cloudflare Access الخاصة بك وتسجيل الخروج، وفحص السلامة، ورابط اشتراك
  التقويم، والنسخة الاحتياطية وواجهة البرمجة، والشيفرة المصدرية وبناء الصور. وهو تحت الإعدادات في الشريط الجانبي. ويرى المسؤولون
  أيضًا موارد النظام في الإحصاءات؛ ولا يراها غيرهم. والمسؤولون المذكورون في `HUNT_ADMINS` مسؤولون
  كلما بدأ hunt؛ والأول هو الحساب 1.
- **سطر الأوامر** يسجّل الدخول برمز خدمة من Access، لا بريد له: اضبط معرّف العميل (Client ID) الخاص
  به رمزًا لسطر الأوامر للحساب في مركز الإدارة، فيعمل سطر الأوامر باسم ذلك الحساب.
- **النسخ الاحتياطية** من إصدارات hunt الأقدم (من المخطط 8 فصاعدًا) تُستورد أيضًا، في الوضعين.
  و**النسخ الاحتياطية** لكل حساب نسخه: النسخة تحوي صفوفه (والملفات التي تستخدمها فقط)، واستيرادها
  لا يستبدل إلا ما لذلك الحساب، بمعرّفات جديدة لا يمكن أن تتعارض مع غيرها.
- مزامنة Gmail لـhunt شخص واحد فقط، حاليًا.
- **التجربة محليًا**: يقدّم `make dev-tenants` (أو `make watch`) الملف `target/dev.db` لعدة أشخاص،
  مع `ADMINS` (افتراضيًا admin@example.test) مسؤولين. لا يوجد Cloudflare Access، فهوية السائل تؤخذ
  على الثقة (`--identity-header X-Hunt-User`): في المتصفح، افتح `/dev/as?email=admin@example.test`
  لتكون المسؤول، أو أي بريد آخر لتكون قادمًا جديدًا يطلب حسابًا؛ و`/dev/as` وحده يسجّل الخروج. لا
  تشغّله هكذا أبدًا حيث يمكن للآخرين الوصول إلى hunt.

## صافي الأجر (المملكة المتحدة)

في الشريط الجانبي، موسومًا بـ«تجريبية»: لمن يقولون إنهم يعيشون في المملكة المتحدة (الإعدادات ←
الموقع)؛ ويُطلب ذلك من غيرهم. ويمكن أن يرافق الراتبَ مكافأةٌ مستهدفة (بمضاعفك ومضاعف الشركة)،
ومكافأة توقيع، ومنح أسهم (RSUs، وخيارات unapproved وEMI وCSOP وSharesave، تُستحق على مدى السنوات،
وتُفرض عليها الضريبة كما يقول gov.uk)، ومزايا عينية (سيارة شركة ووقودها، وشاحنة، وتأمين طبي،
وقرض) وتوقّع سنة بسنة (`src/equity.rs`). معلومات الأجر أولًا: الأجر الإجمالي المعروض أو صافي الأجر
المرغوب؛ موظفًا (PAYE)، أو متعاقدًا داخل IR35 أو خارجه، أو الثلاثة جنبًا إلى جنب؛ والمبلغ وعملته
وفترة الدفع (من الساعة إلى السنة). يحسب ما يبقى من الراتب بعد ضريبة الدخل والتأمين الوطني وقروض
الطلاب والمعاش (التضحية بالراتب، أو صافي الأجر، أو الإعفاء عند المصدر)، بالسنة والشهر والأسبوع
واليوم؛ وما يبقى من أجر المتعاقد (بالساعة أو اليوم أو الأسبوع أو الشهر أو السنة) داخل IR35 (عبر
شركة مظلّة) وخارجه (عبر شركتك المحدودة: راتب، وضريبة الشركات، وأرباح أسهم)، جنبًا إلى جنب، كلٌّ
مع الراتب الذي يعادله. أو بالعكس: من صافي الأجر الذي تريده، الراتب، أو الأجر على جانبي IR35، الذي
يُبقيه. ويمكن كتابة الأجر بعملة أخرى، يُحوَّل إلى الجنيه بسعر اليوم. والطلب الذي يذكر أجره يعرض ما
سيُبقيه نطاقه شهريًا، مع رابط لحسابه. وأقسام مطويّة لرمز ضريبي (1257L، ورموز K، وBR، وD0، وNT…)،
مع الرمز الذي تعطيه الأرقام موصًى به كما تحسبه HMRC (إرشادات gov.uk حول الرموز الضريبية ودليل
PAYE)، وبدل الزواج، وقروض الطلاب، ومعاش مكان العمل (حصتك وحصة صاحب العمل)، وسن معاش الدولة،
وإعانة الطفل ورسوم الدخل المرتفع عليها، والتضحية بالراتب الأخرى (Cycle to Work، وسيارة كهربائية)،
وGift Aid والتبرع من الراتب. وتُقارن النتائج بصافي الأجر الذي تريده (الإعدادات ← صافي الأجر
المرغوب)، الذي يبدأ منه الحساب العكسي. إنجلترا وويلز وأيرلندا الشمالية، أو اسكتلندا؛ والسنتان
الضريبيتان 2025/26 و2026/27 (`src/takehome.rs`).

## التجارب

الميزات التي ما تزال قيد التجربة معطّلة ما لم تُفعَّل حين يبدأ hunt، وحينها للحسابات المسمّاة فقط
(`--experiment name=you@example.com`، أو `HUNT_EXPERIMENTS`). لا يوجد شيء منها الآن؛ وقد صار
`take-home` ميزة، وما يزال مقبولًا، فالخادم الذي يبدأ به يظل يبدأ.

## تشغيل hunt للآخرين: إشعار الخصوصية والشروط والتذييل

تنتهي كل صفحة بتذييل يقول من صنع hunt، ويربط بشيفرته المصدرية (`HUNT_SOURCE_URL`، إن كنت قد
غيّرت hunt: فرخصة AGPL تطلب من الخدمة التي يستخدمها الناس عبر الشبكة أن تتيح لهم شيفرتها).

حين تشغّل hunt لأناس آخرين، تكون مسؤولًا عن بياناتهم، ويطلب القانون (في المملكة المتحدة والاتحاد
الأوروبي، على الأقل) إشعار خصوصية وشروطًا وتفاصيل شركتك. قل من أنت، ويحملها hunt:

| الإعداد | |
|---|---|
| `HUNT_LEGAL_COMPANY` | الاسم المسجّل (مثل `Arabesque Labs Ltd`): ضبطه يفعّل البقية |
| `HUNT_LEGAL_NUMBER` | رقم الشركة (مطلوب) |
| `HUNT_LEGAL_OFFICE` | عنوان المكتب المسجّل (مطلوب) |
| `HUNT_LEGAL_EMAIL` | حيث يراسلك الناس بشأن بياناتهم (مطلوب) |
| `HUNT_LEGAL_REGISTERED_IN` | `England and Wales` ما لم يُذكر غيره |
| `HUNT_LEGAL_SHORT_NAME` | الاسم دون «Ltd»، ما لم يُذكر غيره |
| `HUNT_LEGAL_HOSTING` | أين الخوادم، لإشعار الخصوصية (مثل `the United Kingdom`) |

وفي الصفحات العربية، تظهر الأماكن المعتادة (`England and Wales`، و`the United Kingdom` وغيرهما)
بالعربية، وغيرها كما كُتب.

ثم:

- **`/privacy`**: إشعار الخصوصية (اللائحة العامة لحماية البيانات في المملكة المتحدة والاتحاد
  الأوروبي): من المسؤول، وما يحتفظ به hunt ولماذا، وخدمات تسجيل الدخول، وملفات تعريف الارتباط
  والتخزين (`#cookies`)، ومن يعالج البيانات أيضًا، والنقل، وكم تُحفظ، والحقوق ومكتب مفوّض
  المعلومات.
- **`/terms`**: شروط الاستخدام (للمستهلكين، بموجب قانون إنجلترا وويلز)، وتتناول خدمتك، لا الشيفرة.
- **`/data-deletion`**: كيف تحذف بياناتك: بنفسك، في الإعدادات ← حسابك (يمكن لأي شخص في hunt مشترك
  ذلك، عدا آخر مسؤول فيه)، أو بالطلب. وتطلب خدمة تسجيل الدخول من Facebook هذه الصفحة، وإشعار
  الخصوصية، بعنوانيهما.
- **التذييل** يربط بكليهما، ويعرض اسم الشركة المسجّل ورقمها ومكتبها، كما يطلب قانون المملكة المتحدة
  من موقع الشركة.
- **طلب حساب** يتطلب الموافقة على الشروط. وأيّ إصدار، ومتى، يُحفظ مع الحساب، ويُعرض للمسؤولين
  (`agreed_terms`).

ولكلٍّ منها نسخة عربية تحت `/ar/` (`/ar/privacy`، `/ar/terms`، `/ar/data-deletion`)، تقول إنها
ترجمة وإن النص الإنجليزي هو المعتمد.

النص نص معامل آرابيسك، في `src/web/legal/` (والعربي في `src/web/legal/ar/`): اجعل من يراجعه
لخدمتك قبل الاعتماد عليه. ولا تحتاج أيٌّ من الصفحتين إلى تسجيل دخول، فيمكن للناس قراءتهما قبل
التسجيل: مع حماية Cloudflare Access لـ`/app` و`/api` فقط (انظر أعلاه)، هما كذلك.

## اللغات

تتحدث واجهة الويب الإنجليزية والعربية (الإعدادات ← عام ← اللغة والمنطقة). الإنجليزية، وهي
الافتراضية، تُقرأ من اليسار إلى اليمين؛ والعربية من اليمين إلى اليسار: ينتقل الشريط الجانبي إلى
اليمين، وتسير أعمدة اللوحة من اليمين إلى اليسار، وينعكس كل شيء معها. وتُقدَّم الصفحة مضبوطة مسبقًا
على اللغة المختارة، فتُرسم بالاتجاه الصحيح من البداية.

وللموقع العام (الصفحة الرئيسية، واللقطات، وهذا التوثيق، والصفحات القانونية) نسخة عربية تحت
`/ar/`، يربط بها رابط «العربية» في الترويسة، و«English» عائدًا. وهذا التوثيق بالعربية هو
`README.ar.md`: حدّثه مع `README.md`.

- **ما يُترجم**: كلمات hunt نفسه: القوائم والأزرار والعناوين والنماذج والرسائل والخيارات التي تقدّمها
  الخدمة (المراحل والأسباب والأنواع). وما كتبه الناس يبقى كما كُتب: الأسماء والإعلانات والرسائل
  والملاحظات والوسوم وجمل سجل التغييرات (تكتبها الخدمة، بالإنجليزية). وأسماء المراحل الافتراضية
  تُترجم حيث تُعرض، وتبقى كما هي في قاعدة البيانات. وسطر الأوامر يتحدث الإنجليزية.
- **المنطقة**: كيف تُكتب التواريخ والأوقات والأرقام. وإن تُركت على افتراضيها، تتبع اللغة (أسماء الأشهر
  والأيام بالعربية، مثلًا).
- **الأرقام**: أرقام اللغة نفسها (العربية الهندية، ٠١٢٣، للعربية)، أو الغربية (0123) دائمًا أو
  العربية الهندية دائمًا. والعناوين والبريد وأرقام الإصدارات تحتفظ بأرقامها. والمبالغ
  (<span dir="ltr">£85k–100k/yr</span>) تُقرأ من اليسار إلى اليمين داخل النص العربي.
- **المنطقة الزمنية** (الإعدادات ← التقويم): ما «اليوم» و«الآن»، لـhunt وللصفحة: متى أُضيفت الأشياء،
  وما تأخّر، والتقويم. وإن تُركت فارغة، فهي منطقة الجهاز الذي يعمل عليه hunt (الحاوية عادةً UTC).
  ومع اختيار منطقة، يعطي رابط اشتراك التقويم أوقاته بها (`TZID`).

### إضافة لغة

1. انسخ `src/web/i18n-ar.js` إلى `src/web/i18n-<code>.js`، وغيّر رمزه واسمه واتجاهه (`ltr` أو
   `rtl`) وأرقامه، وترجم كل عبارة. والأنماط تملأ `{names}` بالأجزاء المتغيّرة؛ و`{n}` و`{m}`
   و`{n1}` … لا تطابق إلا الأرقام. والعبارة المتروكة تظهر بالإنجليزية.
2. أضفها إلى `LANGUAGES` في `src/service.rs`، وقدّمها بجانب `/i18n-ar.js` في `src/api.rs`،
   وحمّلها في `src/web/index.html` بعد `i18n.js`.

تُترجم الصفحة أثناء رسمها (`src/web/i18n.js`): الشيفرة تكتب بالإنجليزية، وكل نص وعنصر نائب وعنوان
وaria-label وalt موجود في الفهرس يُستبدل بترجمته. وما داخل `translate="no"`، أو في قائمة محتوى
المستخدم هناك، يُترك كما هو.

## سطر الأوامر

كل أمر عدا `serve` يخاطب الخدمة (`--url`، أو `$HUNT_URL`؛ والافتراضي `http://127.0.0.1:4848`).
ويمكن تسمية العملية بمعرّفها أو بكلمة تميّزها (`acme`). ويمكن أن تكون التواريخ ودّية: `tomorrow`،
`+3d`، `-1w`، `fri 15:00`، `10-30`، `2026-10-30`.

```sh
hunt                                        # the board
hunt add --link https://jobs.ashbyhq.com/acme/1234 -s applied   # read the posting
hunt add Acme -r "Staff Engineer" -s applied --source referral --applied -3d
hunt add TikTok --next "reply to recruiter" --due "fri 10:00"
hunt move acme interviewing                 # --top to put it first
hunt step acme "system design" --at "fri 15:00"
hunt person acme "Sam Lee" --role hiring-manager
hunt note acme "asked about the team's on-call"
hunt next acme "send availability" --due tomorrow
hunt archive tiktok role-closed -n "hiring freeze till November"
hunt archive acme role-filled -n "went with an internal candidate"
hunt resume acme screening
hunt show acme                              # everything, with its change log
hunt board --all                            # every archived process, not just the last 30 days

hunt upload Resume cv.pdf --tag rust-focused   # the next version (the document is made if new)
hunt attach acme resume                     # sent its latest version with acme (--version N)
hunt detach acme 7                          # take version #7 off
hunt download 7 -o ~/Desktop/cv.pdf

hunt lookup ashbyhq.com                     # what a company's site (or LinkedIn page) says
hunt lookup linkedin.com/company/ashbyhq --save   # add it, or fill in what it's missing

hunt mail list acme                         # a process's emails; `hunt mail show 12` reads one
hunt mail import acme ~/Downloads/offer.eml
pbpaste | hunt mail import acme -           # after Gmail's Show original → Copy to clipboard
hunt mail rm 12

hunt tag applications 4 +remote "dream job" -fintech   # add and remove tags; no changes shows them
hunt list applications --where tag=remote

hunt backup                                 # everything, to hunt-backup-<date>.json (-o to choose)
hunt restore hunt-backup-2026-10-06.json    # replace everything with it (asks; --yes not to)

hunt list applications -q rust              # any resource: stages, companies, people,
hunt get companies 3                        #   applications, processes, steps, notes,
                                            #   documents, versions, lanes, tags
hunt edit applications 4 location=London salary_min=150k currency=GBP work_mode=remote
hunt new people name="Pat Chen" company_id=acme title=Recruiter
hunt rm stages 6 --move-to applied
hunt list reasons                           # the reasons for closing: the terminal stages' lanes
hunt new lanes stage_id=their name="Salary too low"    # another reason
hunt edit stages 3 active=0                 # terminal: what's in it closes
hunt new swimlanes name="On hold"           # another row of the board
hunt order considering applied screening interviewing offer
hunt fields applications                    # what each resource has
hunt log processes 12                       # the change log
```

المزيد في [`docs/design.md`](docs/design.md) (بالإنجليزية).
